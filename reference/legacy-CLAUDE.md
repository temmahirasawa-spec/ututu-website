# UTUTU コーポレートサイト｜引き継ぎ

このリポジトリは、株式会社UTUTU のコーポレートサイトです。
現在は **トップページのヒーロー（KV）のみ** が静的HTMLで完成しています。
ここから Next.js に載せ替えて、他のページを含む本番サイトを構築します。

### 場所

```
Dropbox/UTUTU/コーポレートサイト/
├─ UTUTU_Website/   ← このリポジトリ。ここで開発し、Vercelに出す
└─ KV/              ← 素材の作業場。マスター動画と書き出しの中間ファイル
```

`KV/` はリポジトリではありません。連番を作り直すとき（`ffmpeg` で
`master2.mp4` から書き出すとき）だけ触り、結果を `UTUTU_Website/` に
コピーします。原本を git に入れないのは、数百MBを毎回転送しないためです。

---

## 1. いま何が動いているか

`index.html` 一枚で完結する、**スクロール連動の画像シーケンス**です。
Apple の製品ページで使われている方式で、動画をコマ送りするのではなく、
連番の静止画をスクロール量に応じて canvas に描いています。

体験の流れは4章です。

| 章 | 内容 | 映像 |
|---|---|---|
| 0 | 店舗に、いい一日を。 | 外観 |
| 1 | この店が、開発室です。 | 店内へ入る |
| 2 | 埋もれる一品を、なくす。 | テーブルで**停止**。スマホ画面に GOOD ORDER のUIを合成 |
| 3 | ほめ言葉は外、苦言は内。 | 別アングルで**停止**。GOOD REVIEW のUIを合成 |

そのあと白背景のプロダクト紹介セクション（`#after`）へ続きます。

## 2. 素材

すべて `master2.mp4`（1920×1080 / 24fps / 824コマ）から書き出したものです。
マスター動画はリポジトリに含めていません（`.gitignore` 参照。Dropboxの
`UTUTU/コーポレートサイト/KV/` に原本があります）。

```
frames/       f_0001〜f_0295.webp   1280×856   約13MB   横位置（PC）
frames_p/     f_0001〜f_0295.webp   720×1278   約8MB    縦位置（スマホ）
frames_lo/    f_0001〜f_0295.webp   320×214    約2MB    横位置の先読み用
frames_lo_p/  f_0001〜f_0295.webp   240×426    約2MB    縦位置の先読み用
clips/        good-order-clip.mp4 / good-review-clip.mp4  端末画面に流す映像
```

スマホは 10MB、PCは 15MB。向きごとに片方しか読みません。

### 番号の三段構え（ここが分かりにくい）

| | 範囲 | 何か |
|---|---|---|
| 仮想コマ | 1〜1189 | スクロール量。停止区間を含む |
| 実コマ | 1〜589 | 映像としてのコマ番号。**停止点も四隅の座標もこの番号** |
| ファイル | 1〜295 | 実際に置いてある枚数 |

仮想→実は `resolve()`、実→ファイルは `fileOf()` が担当します。

**ファイルは1コマおき（24fps→12fps）です。** ファイル k は元の
`f_{2k-1}` にあたります。転送量と本数が半分になり、見た目はほぼ変わり
ません（章送りの移動は元から毎秒50〜130コマ進むので、24fpsぶんの
コマは表示しきれていません）。停止点の 447 と 589 は、ちょうど
224 と 295 に残るよう奇数側を採ってあります。

**低解像度は縦横の比率を高解像度と完全に一致させること。**
横 1280×856 → 320×214（1/4）、縦 720×1278 → 240×426（1/3）。
比率がずれると `cover` の切り取りが変わり、はめ込み座標が合わなくなります。
以前 `frames_lo` が横位置専用だったのはこれが理由でした。

## 3. 中核の仕組み

### 3-1. 仮想コマ番号と停止点

```js
CFG.holds = [
  { at: 447, len: 220, ui: 'order',  land: [...], port: [...] },
  { at: 589, len: 220, ui: 'review', land: [...], port: [...] }
]
```

`at` のコマで映像を止め、`len` コマ分のスクロールをそこで消費します。
`resolve(virtualFrame)` が「実コマ番号」と「いまどの停止点にいるか」を返します。
停止点は何個でも増やせます。

**スクロールと仮想コマは、停止区間を詰めた座標系で結んでいます**
（`compress` / `expand` / `SCROLL_RATE = 0.3`）。素の比例にすると、
停止区間が**スクロールの43%（578px×2）を食い、その間まったく絵が変わりません**。
0.3 に詰めると 18% まで下がります。詰めすぎると停止点を一瞬で通り過ぎるので、
0.3 前後が上限と下限の間です。章送りの補間だけは別で、押した瞬間に動き出すよう
`TWEEN_RATE = 0.05` とより強く詰めています。

**さらに、停止のあいだは #stage をゆっくり寄せています**（`updateOverlays` の
`zoom`。最大4.5%、`sin` なので両端で1.0に戻り継ぎ目が出ない）。canvas と
はめ込みは同じ `#stage` の中なので一緒に拡縮され、ズレません。
**編集モードとスマホでは掛けません。** スマホの章送りは停止区間を数%の時間で
駆け抜けるため、着地際に拡大が一瞬で入ってカクついて見えます。そもそも
「スクロールしても動かない」はPCの自由スクロール固有の問題です。

**スクロール量を減らしたいときは `len` だけを触っても効きません。**
ページの高さは `#track` の `.beat` の枚数（1枚＝画面1つぶん）で決まっていて、
`len` はその中での配分を変えるだけです。減らした分は他の区間に回ります。
実際 `len` 300→220 では、3→4の占有率が 37.2%→35.2% にしか動きませんでした。
**`.beat` の枚数と併せて調整してください**（いまは4枚＝3画面ぶん。
5枚だった頃より3→4が 1.49→1.06画面ぶんに縮んでいます）。

### 3-2. スマホ画面へのUI合成（ホモグラフィ）

映像に写っているスマホの画面に、**HTMLで書いたUIを透視変換で貼り込んで**います。
生成AIに画面を描かせると文字が崩れるため、画面は消灯状態で撮り、
上からHTMLを重ねる設計にしました。文字が常にくっきり読め、あとから
文言も差し替えられます。

- `homography(dst)` … 390×844 の矩形を、実測した四隅に写す行列を解く
- 結果を `matrix3d` として `.slot` 要素に適用
- `#tint`（乗算）と `#sheen`（スクリーン）を重ねて貼り物感を消す

四隅の座標は**実機で測った実測値**です。計算では合いません。
調整用に `?edit=1` または **Eキー** で編集モードが開き、緑の丸を
ドラッグすると座標が出ます。停止点ごと・画面の向きごとに切り替わります。

### 3-3. 読み込み

同時8本の優先度付きキュー（`pump()`）。いま見ているコマに近いものから、
低解像度を先に取ります。

**ローディング画面を閉じる条件は2つ揃ったときです**（`loadProgress()`）。

1. 先読みの低解像度が揃っている（どのコマに飛んでも絵がある）
2. 冒頭 `headHi` 枚が高解像度で揃っている（最初の画面が粗くない）

先読みは**4枚に1枚だけ**取ります（`loStep` / `lowList()`）。全編を1枚ずつ
取ると295往復かかり、実測で2.2MBに3.9秒でした。**遅いのは容量ではなく
往復の回数です。**間引けば76往復で済みます。欠けたところは直前のコマを
出しますが、元が12fpsなので最大0.25秒ぶんの差で見分けがつきません。
**停止点のコマだけは必ず含めます。**そこはUIを重ねる位置なので、別の
コマが出ているとはめ込みがずれて見えます。

片方だけだと、粗い絵のまま操作できてしまうか、待ち時間が長すぎます。
回線が細いときのために `maxWait`（15秒）で打ち切ります。

同時本数について。以前は4本でした。HTTP/1.1 のローカルサーバーで
接続が埋まるのを避けるためでしたが、**Vercel は HTTP/2 なので
1本の接続に多重化され、8本でも埋まりません。** 実測で 295枚が
4本で約7秒、8本で約4.5秒でした。増やしすぎると逆に遅くなります
（24本では半分の速度に落ちました）。

### 実測（スマホ・縦位置）

| | 所要 |
|---|---|
| 初回・エッジ温 … ローディングが閉じるまで（136件） | **1.5秒** |
| 初回・エッジ温 … 残りの高解像度（235件） | 2.8秒 |
| 2回目以降（ブラウザキャッシュ） | ほぼ即時 |
| **デプロイ直後の最初の1人**（エッジ冷） | 12秒 |

最後の行だけが遅いので、**デプロイのあとは必ずエッジを温めてください。**

```bash
sh scripts/warm.sh                          # 本番
sh scripts/warm.sh https://xxx.vercel.app   # プレビュー
```

**素材は1年 immutable で配信しています**（`vercel.json` の `headers`。
なお `vercel.json` はコメントを書けません。`"//"` のようなキーを足すと
スキーマ検証で落ちてデプロイが失敗します）。URLに
`?v=` を付けているので、**連番を作り直したら `CFG.ver` を必ず上げて
ください。**上げないと、一度見た人のブラウザは古い絵を使い続けます。

### 3-4. スマホの章送り

スマホ（`innerHeight / innerWidth > 1.15`）では**指のスクロールを無効化**し、
下部のNEXT／BACKボタンと右側のドットだけで章を移動します。
どこまでスクロールすればよいか分からない不安を消すためです。

**章はピクセルではなくコマ番号で持ちます**（`chapters` ＝ 仮想コマ、
`chapY(i)` が現在の `heroMax` で換算）。iOSはURLバーの出入りで
`innerHeight` が変わり `heroMax` が縮みます。ピクセルで覚えておくと、
縮んだあとは同じ座標が別のコマを指し、**最後の章は heroMax を超えて
到達不能になり、移動が途中で止まります**（実際にそうなりました）。
`gotoChapter` の行き先もコマから直に取ること（ピクセルへ往復させない）。

章は4つ（冒頭 / 入店 / GOOD ORDER / GOOD REVIEW）。**最後のNEXTは
映像を抜けて `#after` まで送ります**（`gotoAfter`）。映像を抜けると
`past-hero` が付いて送りUIは消えます。スマホでは SCROLL の案内は出しません。

移動時間は区間ごとに `CHAPTER_DUR = [1300, 1700, 2100]`。
**遅くしすぎるとコマ送りに見えます。**素材は1コマおき（12fps）なので、
4200msでは毎秒18枚しか出ず、はっきりカクつきました。いまは35枚/秒前後です。
距離ではなく区間で決めています（距離基準だと、見た目が変わらない
停止区間にも時間を配分してしまい、肝心の移動が速く見えるため）。

**停止区間は「見た目の距離」に換算してから補間します**（`visualOf` /
`virtualOf` / `HOLD_RATE`）。停止点の真ん中にいる章から動き出すとき、
素の仮想コマで補間すると最初の150コマぶんは同じ絵のままで、
押しても1秒近く何も起きないように見えます。停止区間を 0.05 倍に
数えることで、この空白が 0.02〜0.26 秒に縮みます。

`easeMove` は**等速（`t` をそのまま返す）**です。イーズアウトを入れると、
着地の直前に数コマだけ動く尾が残って気になります。

**送り中は `cur` の補間を切ってあります**（`tick` の `if (tweening) cur = target`）。
指の操作のための指数追従をそのまま効かせると、スクロールが止まったあとも
しばらく絵が動き続け、これも尾になります。

### コピーの出入り

**開始は停止点より手前に置くこと**（`COPY_AT`）。停止区間に入ってから出すと、
章の移動の9割を過ぎてからの出現になり、章ごとに出方がばらつきます
（直す前は 2枚目70% / 3枚目92% / 4枚目94% でした）。いまの値は、
どの章でも**移動の約70%**で出そろうように引いてあります。

**区間どうしを重ねないこと。** 重なったコマでは両方が不透明度1になり、
同じ位置に2つの文章が出ます（`[230,430]` と `[417,717]` で13コマ重なっていて、
移動中だけ2枚が並んでいました）。隙間は狭いと消えきる前に次が出て重なり、
広いと文字のない時間が延びます。**どの区間も無表示が 0.3〜0.4 秒**に
なるよう引いてあります。3枚目の終わりが停止点より後ろ（`+73`）なのは
そのためで、停止点で切ると2.4秒も文字のない時間ができます。

**濃度はコマ数ではなく時間で動かします**（`COPY_FADE_SEC = 0.38`）。
章によって毎秒進むコマ数が4倍以上違うため、コマ基準にすると
速い区間では一瞬で切り替わってカクつき、遅い区間ではだらだら続きます。
`updateOverlays` には**丸めていない `cur`** を渡してください。丸めると段になります。

移動中でも次の操作を受け付けます（`tweenToken` で古い移動を破棄）。

## 3-5. ローディングの線画

**線画は画面いっぱいに、映像と同じ切り取り方で置いています**
（`preserveAspectRatio="xMidYMid slice"` ＝ canvas の cover と同じ）。
こうすると、明けたときに1コマ目とそのまま重なります。小さく中央に置くと、
次に出る映像とつながらず、何の絵だったのか分からなくなります。

**縦位置では viewBox を差し替えます**（`ART_VB` / `setArtView`）。線画は
横位置の画角で描かれていますが、縦の連番は**横位置の x 400〜879 の範囲**しか
写していません（1コマ目どうしの相関で実測、一致度 0.988）。差し替えないと
画角がずれて重なりません。

ロゴ（`#loadMark`）は、読み込み後の `#brand` と**同じ大きさ・同じ位置**に
置いてあります（`--markCap` / `--markBox` / `--markY` を共有）。明けたときに動きません。

### ロゴの遊び

明けて9秒後から、**30秒ごとに2つの動きを交互に**します（`startMarkPlay`）。
UTUTU は回文で、1文字84・字送り110の等間隔に並んでいます。

| | 中身 | 所要 |
|---|---|---|
| すべる | 位置を入れ替える（U3つが順ぐり、T2つが交換）。**語は UTUTU のまま** | 2800ms |
| 裏返す | 位置は変えず、左から1文字ずつ左右反転。どの文字も左右対称なので形は同じ | 1250ms＋210msずつずらし |

どちらも**終わった状態が正しい並び**なので、何度くり返しても崩れません。
語が変わらない入れ替えは全12通りあり、そのうちの1つを使っています。

- **1文字は2段の `g`**。外側が位置、内側が反転。分けないと2つの動きを別々にかけられません
- 数値は `MARK`（`slideDur` / `flipDur` / `flipGap` / `first` / `every`）に集めてあります
- 影に **CSS の `filter:drop-shadow` を使わないこと。** 適用範囲が要素の外接矩形の
  ±10%に固定されるため、文字が動いてそこから出た部分が消えます。しかも外接矩形は
  動きの途中で変わるので、症状が出たり出なかったりします。
  SVG の `<filter filterUnits="userSpaceOnUse">` なら範囲を明示できます
- `prefers-reduced-motion` では動かしません

**ロゴは押せます**（`gotoTop`）。スマホは1つ目の章と同じ動き、PCも同じ速さで
先頭まで戻します。

## 3-6. スクロールの位置表示（PC）

右側の縦棒（`#prog`、5×360px）が映像区間の進み具合を示します。`prog`（0〜1）を
そのまま塗りの高さにしているだけです。映像を抜けると消えます。
**スマホでは出しません**（章送りのドットがあるため）。

**映像区間のあいだは、OS標準のスクロールバーを隠しています**（`syncChrome`）。
クラス `hide-sb` は **`<html>` に付けます**。スクロールバーは根の要素のものなので、
`body` のクラスからは指定できません。

注意点がひとつ。macOS で「スクロールバーを常に表示」にしている人は、
映像を抜けた瞬間にスクロールバーが現れ、**その幅ぶん（約15px）レイアウトが動きます**。
既定の「自動」設定なら重ね表示なので幅を取らず、動きません。
気になる場合は、ページ全体で隠しきる（`hide-sb` を外さない）のが手です。

## 3-7. 文字組みとロゴ

- **タイトルに `<br>` を入れない。**読点の位置で折らず、幅で自然に折り返す
- 和文タイトルの下に英語を1行置く（`.copy .entitle`）。
  **`.copy p` のほうが詳細度が高いので、`.copy` を前に付けないと打ち消されます**
- **欧文は Barlow、和文は見出し Zen Kaku Gothic New / 本文 Noto Sans JP。**
  `font-family` の先頭を Barlow にすれば、和文グリフを持たないぶん
  日本語だけが次に落ちます（`--jp-title` / `--jp-body`）
- **ロゴは正式版**（`UTUTU_CorporateWebsite/public/images/logo.svg`）です。
  塗りのアウトラインで `viewBox="0 0 1160 149"`、余白8、**1文字152・字送り248・
  高さ133**。原本は5文字が1つの複合パスなので、**アニメーションのために1文字ずつ
  分けて**あります（局所座標は U と T の2種類だけ）。`fill-rule="evenodd"` が必要
- ロゴとハンバーガーは `--markCap`（文字の高さ 17px）と `--markY`（中心線 41px）で
  揃えてあります。SVGの箱は `--markBox` ＝ `--markCap × 149/133`。
  **片方だけ動かさないこと**（実測でどちらも 17px・中心 41px）

## 3-8. 紙のセクション（#after）

映像を抜けたあとの本文。構成は6ブロック＋フッターです。

| | 役割 |
|---|---|
| 受け | 映像の余韻を引き取り、紙に切り替える。二枚看板（店をつくる／道具をつくる）の宣言 |
| 私たちがつくった店 | **左右いっぱいの写真の帯**（2列が逆方向にゆっくり流れる）＋名前の列。準備中の店の写真も混ぜてよいが、**一覧に載せるのは営業中の店だけ** |
| 橋 | 「既製品は現場に合わなかった」。**墨に反転**し、数字の帯を見せる |
| GOOD ORDER / GOOD REVIEW | 紙に戻る。図解が主、文章は補助 |
| Founders | 独立セクション。丸＋名前＋一言＋PROFILEボタン。**全文はモーダル**（SP=下からのシート / PC=中央ポップアップ、`#bioModal`）。丸（`.fd-ph`）は後日ローポリ3Dの canvas に差し替える受け皿 |
| 締め | 「検証は、今日も営業中。」**墨に反転**。営業中ランプ |
| フッター | 会社概要・お問い合わせは別ページ予定。いまは（準備中） |

### 紙⇄墨の反転（inkSync）

`data-ink` の節が画面の中ほどに来ると、`#after` に `.inked` が付いて
**紙 → 墨** に反転します。色はすべて `#after` のトークン
（`--pg` `--tx` `--mut` `--acc` `--ln` `--bd`）経由で、**個々の要素に
直接色を書かないこと**。書くと反転から取り残されます。

- 色の変わり目は各要素の `transition` が担う。**`.rv` の transition には
  color / border-color も入れてある**。`.rv` を持つ要素に別の transition を
  書くと上書きされて反転が飛ぶので注意
- 反転はページ内で2回だけ（橋と締め）。増やすと安っぽくなります

### 写真の帯（band）

同じ組（`.set`）を2つ並べ、`translateX(-50%)` のループで切れ目なく流します。
**組と組の間隔は `.set` の `padding-right` で作る**こと（row に gap を書くと
半分の位置がずれて、ループの継ぎ目が跳ねます）。「流れる」の語彙は
**この節だけ**に限定。写真は `img/brands/`（高さ480、計約330KB）。

- **img には必ず width / height 属性を付けること。** 高さ固定・幅autoの
  レイアウトなので、属性が無いと読み込み前は幅0になり、**行ごと潰れて
  何も見えず、読み込んだ瞬間に突然現れます**（モバイルで実際に起きた）
- **速さは bandSpeed() が画素/秒で決めます**（上段62 / 下段50 px/s）。
  CSSの秒数は仮置きです。`%` 基準のままだと、幅の細いモバイルでは
  同じ秒数でも画素速度が半分になります

### 図解の差し替え（イラレで作る人へ）

いまの図はサンプルです。`.fig` の中の `<svg>` を差し替えれば、線引きの
アニメーションは自動で掛かります。規則はローディングの線画と同じ：

- **アートボードは1図につき2枚**。PC `900×430` / SP `480×560`
  （クラス `fig-pc` / `fig-sp`。760px以下でSPに切り替わる）
- **セレクタは `.fig svg.fig-pc` の形で書くこと。** `.fig svg`（0,1,1）が
  `.fig-sp`（0,1,0）に勝つため、クラス単体では display を打ち消せません。
  実際に PC で SP図が二重表示される不具合になりました
- **fill無しのストローク＝線として順に引かれる**（下のレイヤーから）
- **文字と塗り＝線のあとにフェードイン**（アウトライン化した文字も塗り扱い）
- 文字サイズ：PC版は12px以上、**SP版は17px以上**（表示が約0.71倍に縮むため）
- 薄く沈めたい一群は `<g data-dim>` に入れる（引き終わったあと18%へ落ちる）
- **破線に `stroke-dasharray` を使わないこと。** 線引きアニメが dasharray を
  上書きするため破線が消えます。折り目の点線は「短い線の列」で描いてあります
- 図を単体SVGとして書き出して確認するときは `data-dim=""` と値を付けること
  （XMLでは値なし属性が不正。ページ内のHTMLでは `data-dim` のままで合法）

### Founders のアバター（`js/head-viewer.js`）

Founders には **Avaturn で生成した全身アバター（カラー・テクスチャつき）** を表示する
（2026-08-19 天真さん判断：白マネキンより全身カラーが面白い。重さはある程度許容。
重すぎるなら会社概要ページに移す選択肢もあり）。

- モデルは `models/temma.glb`。Avaturn の書き出し（3.8MB）の**テクスチャを512pxに
  縮めたもの**（1.57MB）。`scripts/shrink_textures.py` で作る。
  表示は約270CSS px（DPR2で540px）なので2048pxは過剰。実表示サイズで
  原寸・512・256を並べて比べ、512で見分けがつかないことを確認済み。
  1024はほとんど効果がない（元から大半が1024以下、2048は1枚だけ）
  **Founders が近づいたときだけ動的 import** なので KV の速度には影響しない
- 読み込みは three.js 公式 **GLTFLoader**（`js/GLTFLoader.min.js`、45KB。
  three@0.185 の examples から esbuild で束ね、import を同梱の three に付け替えた自家版）。
  初期に作った自前パーサ（glb.js）は全身・テクスチャ・スキンで割に合わなくなり削除
- **T-Pose のままだと両腕が水平に広がって間抜け**なので、クリップが無いGLBでは
  読み込み時に腕のボーンを体側へ下ろす（`relaxArms`）。ボーンのローカル軸は
  リグ規約に依存しないよう、ワールド空間で「今の向き→目標の向き」の回転を作って
  親の姿勢でローカルへ引き戻す（`aimBone`）
- **採寸は `poseBounds()` で実ポーズから測る。**`Box3.setFromObject` はスキンメッシュだと
  バインドポーズ（T-Pose）の箱を返すので、腕を下ろしても「腕を広げた幅」のまま。
  カメラが無駄に引いて人が小さくなる。`SkinnedMesh.getVertexPosition()` は
  ボーン変形後の頂点を返すのでそれで測り直す。実測で高さ比0.93まで詰まった
- カメラの注視点は 0 のまま。少しでも上げると足元が枠の下端で切れる
- モデルは Avaturn の「Avatar with animation」書き出し。
  入っているクリップは **走り（Mixamo・0.67秒・16コマ）の1本だけ**で、これをループ再生する
- 操作：ドラッグでヨー回転（慣性つき）、タップで**びくっと驚く**。
  驚きは `applyStartle()` が背骨・首・頭・腕のボーンを回して作る。
  **`mixer.update()` のあとに掛ける**ので走りの動きの上に重なり、
  毎フレーム クリップから書き直されるため掛け続けても溜まらない
- **JSとGLBのURLには必ず版番号を付ける（`head-viewer.js` の `VER`、
  index.html の import の `?v=`）。**Vercel は `must-revalidate` だが、
  端末（特にiOS Safari）は古いモジュールやGLBを掴み続ける。
  実際に「修正済みのはずなのに端末では首が折れたまま」という事故が起きた。
  **GLBを差し替えたら VER を必ず上げること**
- **驚きの回転は「掛けて、描いて、すぐ戻す」。**`applyStartle` の前に対象ボーンの
  quaternion を控え、`render()` の直後に書き戻す。次のフレームは必ず mixer が
  書いた状態から始まるので、クリップの中身に関係なく絶対に溜まらない
- **やってはいけない：「クリップにトラックがあるボーンは mixer が毎フレーム
  書き直す」と仮定すること。**three.js は値が前フレームと同じなら
  シーンに書き戻さない（`PropertyMixer.apply` が変化を見て `setValue` を省く）。
  走りのモーションは頭が首に対して静止しているため、**Head のトラックはあるのに
  書き戻されず**、掛けた回転が積み上がって首が90°折れた。
  トラック名で判定する実装は3回作り直して3回とも壊れた。検出に頼らないこと
- 検証は必ず「頭のボーンの基準からのずれ」を連続タップで測る。
  シルエット幅だけでは走りの位相差に埋もれて気づけない

- ボーンのローカル軸はリグ次第で当てにならないので、`nudge()` は
  「ワールドのこの軸まわりに」を親の空間へ持ち込んでから掛ける（リグ非依存）
- **`pointerdown` で即 `setPointerCapture` してはいけない。**アバターの上から
  始めた縦スワイプ（＝ページのスクロール）まで奪ってしまい、ページが遅れて
  追いつくので画面が飛ぶ。アバターを大きくしたら指が乗る面積が増えて表面化した。
  **指が横に動いたと分かってから捕まえる**（縦が勝ったら pointer を手放す）。
  マウスはスクロールと競合しないので pointerdown で即捕獲してよい
- ループの開始は IntersectionObserver 任せにせず、`initHeads` の時点で
  既に画面内なら即 `setRunning(true)`。初回コールバックの遅延で取りこぼさない
- **検証の注意：ブラウザーペインが非表示だと rAF も IntersectionObserver も
  発火しない。**動きを実行時に確かめるには `window.requestAnimationFrame` を
  差し替えてコールバックを溜め、手でフレームを送る。そのうえで
  `gl.readPixels` のシルエット幅で確認できる（走り0.48〜0.54 → 驚きのピーク0.84）
- `poseBounds` は頂点を4つおき・時間を8点に間引く。全頂点×10点だと
  端末によっては数百ms スレッドが止まり、スクロールがつっかえる
- クリップが2本以上あるGLBに差し替えたら、2本目以降を1回流す実装が自動で優先される
  （Avaturn で驚き系のモーションが出せたらそちらのほうが自然）
- **採寸はクリップ全体を10点サンプリングして合成する**。1コマだけで測ると
  走りの途中で手足が枠から出る
- 最初の1フレームは rAF 任せにせず同期 render()（バックグラウンドでも絵が出る／
  失敗が catch に届いてプレースホルダが残る）
- プレースホルダ：`data-head` のGLBが404でも壊れず破線の枠が残る。
  洋輔さんぶんは `models/yosuke.glb` を置くだけで有効になる

## 4. 踏んだ落とし穴（再発させないこと）

### 3Dの頭まわり（今回踏んだもの）

- **`BufferGeometry.scale()` / `applyMatrix4()` は morphAttributes を変換しない。**
  頭を正規化するとき、位置だけ縮んで表情の振れ幅が元のままになり顔が壊れる。
  モーフは差分なので、**倍率だけ自分でかける**（平行移動は不要）
- **`computeBoundingBox()` はモーフを累積で足して多めに見積もる。**
  これに合わせて大きさを決めると顔が必要以上に小さくなる。
  実際に使う表情を1つずつ適用して測ること
- **Blender側でフラットシェードにしてはいけない。**面ごとに頂点が分割され、
  2,500三角面で頂点が6,912個になり容量が3倍（380KB）になる。滑らかなまま
  書き出して、カクカクした見た目は three.js の `flatShading` に作らせる（76KB）
- **書き出しの Draco 圧縮は必ずOFF。**ONだと専用デコーダが要る
- **`jawOpen` を 0.7 まで開けない。**口の内側の面が露出して舌のように見える。
  0.25 で「驚き」に見え、眉（`browInnerUp` / `browOuterUp`）を強く出すのが効く
- **FaceBuilder の頭は下がラッパ状に広がっている。**そのまま穴を塞ぐと
  57角形の耳切り三角化で面が折れ重なる。**首の筒のところで切ってから塞ぐ**
- **モーフ0個のGLBで `geo.morphAttributes.position = []` を代入してはいけない。**
  three.js は空配列でも「モーフあり」と判定し（`void 0 !==` 判定）、0枚の
  モーフテクスチャを作ろうとして最初の render() で落ちる。canvas追加後に
  落ちるためプレースホルダも消えていて、**画面には何も出なくなる**。
  ターゲットがあるときだけ morphAttributes を触ること（head-viewer.js）
- 最初の1フレームは rAF 任せにせず **makeHead 内で同期的に render() する**。
  バックグラウンドタブでも絵が出るし、描画の失敗が catch に届いて
  プレースホルダが残る（無言の空白にならない）
- Blender の `--background` では depsgraph が回らず、**サーフェス変形の
  バインドが効かない**（opは `FINISHED` を返すのに `is_bound` が False）。
  GUIでは動く。ヘッドレスで検証するなら ops に頼らない実装にすること


- **`python3 -m http.server` は Range に未対応** → Safariが動画を再生しない。
  以前は対策として動画をHTMLに埋め込んでいましたが（453KB、HTMLの91%）、
  **Vercelが 206 を返すことを確認したので削除しました。**index.html は
  492KB → 39KB になっています。ローカルは `npx serve` を使ってください。
- **画面の向きが変わると素材そのものが変わる**。読み込み済み画像を
  破棄して読み直さないと、古い向きの絵に新しい座標を当ててずれます。
- **`file://` では動きません。** 必ずサーバー経由で。
- **連番は1始まり、`sheet/` の確認用画像は0始まり。** 番号がひとつずれます。
- **Vercelへのアップロードは24時間5,000ファイルまで**。1,180ファイルあるので
  ドラッグ&ドロップやCLIだとすぐ制限に当たります。**Git経由なら制限なし。**

## 6. Next.js 化の方針

### 構成

```
app/
  layout.tsx
  page.tsx                トップ（KVを含む）
  products/
    good-order/page.tsx
    good-review/page.tsx
  about/page.tsx
  contact/page.tsx
components/
  hero/
    ScrollSequence.tsx    canvas とコマ送り
    ScreenComposite.tsx   ホモグラフィによるUI合成
    ChapterNav.tsx        スマホの章送り
    heroConfig.ts         CFG / holds / CHAPTER_DUR / COPY_AT
public/
  frames/ frames_p/ frames_lo/ clips/
```

### 移植の要点

- **canvas への描画ロジックはそのまま移植できます。** `next/image` は使わず、
  素の `new Image()` で読み込んでください（canvas に描くため）。
- 連番は `public/` 直下に置き、パスは `/frames/f_0001.webp` の形。
- 設定値（`CFG.holds` の座標、`CHAPTER_DUR`、`COPY_AT`）は
  `heroConfig.ts` に切り出し、**マジックナンバーを散らさない**こと。
- `useEffect` 内で読み込みキューを起動し、アンマウント時に必ず破棄。
- 編集モード（`?edit=1`）は開発時に必須なので**残してください**。
  座標の再調整は今後も発生します。
- 埋め込み動画は静的版の時点で削除済みです。
- `vercel.json` の `headers`（素材を1年 immutable）を引き継いでください。
  Next.js では `next.config.js` の `headers()` でも同じことができます。

### プロジェクト共通の約束

- Vercel の function region は東京 `hnd1`（`vercel.json`）
- トグルやチェックの操作は楽観的更新にする
  （UIを即反映 → 裏で保存 → 失敗時だけ巻き戻す）
- `await action()` のあとに `router.refresh()` を同期的に呼ぶ形は避ける
- フォント（Google Fonts）
  - 見出し … Zen Kaku Gothic New Medium(500)　`--jp-title`
  - 本文 … Noto Sans JP Regular(400)　`--jp-body`
  - 欧文 … Barlow（両方の先頭に置いてある。和文グリフを持たないので日本語は次に落ちる）
  - **見出しは字間をあけること**（PC `.09em` / スマホ `.07em`）。
    ただし**あけすぎるとスマホで表題が2行になり、はめ込みに食い込みます**。
    12文字の表題が402px幅で1行に収まるのが上限です

### Dropbox の同期から外してあるもの

このリポジトリは Dropbox の中にあります。`node_modules` をそのまま置くと
数万ファイルが同期対象になり、Dropbox が延々と回り続けます。そこで
`node_modules` と `.next` に Dropbox の無視属性を付けてあります。

```bash
xattr -p com.dropbox.ignored node_modules   # 1 と出れば効いている
```

**フォルダごと消して作り直すと属性も消えます。** `rm -rf node_modules` の
あとは、`pnpm install` の前に付け直してください。

```bash
mkdir -p node_modules .next
xattr -w com.dropbox.ignored 1 node_modules
xattr -w com.dropbox.ignored 1 .next
```
